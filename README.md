# Stream Notify Bot

Discord-бот отслеживает трансляции на Twitch и YouTube и отправляет уведомления на настроенные серверы. Управление — через веб-панель с авторизацией Discord. Интерфейс доступен на русском и английском; язык переключается в верхней части страницы и сохраняется в браузере.

Проект создан на основе [stream-notify-bot](https://github.com/Sufiyxn/stream-notify-bot) от [Sufiyxn](https://github.com/Sufiyxn). Исходный проект распространяется под лицензией MIT.

## Возможности

- Отдельные настройки, канал уведомлений и список стримеров для каждого Discord-сервера.
- Обзор состояния стримов, времени последней проверки и ошибок доставки.
- Добавление, изменение, удаление и пауза уведомлений для отдельных стримеров.
- Простой текст или embed с предпросмотром; по желанию сообщение удаляется после окончания трансляции.
- Привязка стримера к участнику Discord и упоминание роли.
- Изменение настроек и API-ключей через панель с применением на лету.
- Сохранение состояния доставки в SQLite и проверка истории канала при повторной отправке.

Для управления сервером пользователь должен иметь права администратора на этом сервере. Общие токены доступны только владельцу бота, указанному в `.env`.

## Запуск через Docker

Понадобятся Docker с Compose, Discord-приложение и HTTPS-адрес с настроенным обратным прокси. Для локального доступа с той же машины можно использовать HTTP на `127.0.0.1`.

### 1. Подготовьте Discord

1. Создайте приложение в [Discord Developer Portal](https://discord.com/developers/applications), добавьте бота и получите его токен.
2. В OAuth2 добавьте Redirect URI `https://YOUR-DOMAIN/callback` (для локального запуска — `http://127.0.0.1:8765/callback`). Скопируйте Client ID и Client Secret приложения.
3. В разделе Bot включите **Server Members Intent**, чтобы выбирать участников при привязке к стримерам.
4. Узнайте свой Discord User ID: включите режим разработчика в Discord и скопируйте ID своего пользователя.

Ссылка для добавления бота находится на главной странице панели. Пригласите его на нужный сервер и предоставьте доступ к выбранному каналу, отправке сообщений, embed и истории сообщений. Для упоминания роли могут понадобиться дополнительные права или разрешение на упоминание этой роли.

### 2. Настройте окружение

```bash
git clone https://github.com/scatari69/stream-notify-bot.git
cd stream-notify-bot
cp .env.example .env
```

Укажите в `.env`:

```dotenv
DISCORD_CLIENT_ID=ID_приложения
DISCORD_CLIENT_SECRET=секрет_OAuth2
DISCORD_OWNER_ID=ваш_Discord_User_ID
PUBLIC_BASE_URL=https://YOUR-DOMAIN
ADMIN_BIND_ADDRESS=127.0.0.1
ADMIN_PORT=8765
```

`PUBLIC_BASE_URL` — внешний адрес без пути и завершающего слеша; он должен совпадать с адресом в Redirect URI. `ADMIN_BIND_ADDRESS` и `ADMIN_PORT` задают интерфейс и порт на хосте. Если прокси работает на другом компьютере, укажите доступный ему адрес хоста и ограничьте доступ к порту средствами сети или файрвола.

Токен бота, YouTube API key и Twitch Client ID/Secret можно указать в `.env` либо сохранить позже в панели в разделе общих токенов. Значения, сохранённые через панель, имеют приоритет. Не публикуйте `.env` и данные Docker volume.

Для Twitch создайте приложение в [Twitch Developer Console](https://dev.twitch.tv/console/apps). Бот использует Client Credentials, поэтому callback для этого потока не используется; если консоль требует адрес, можно указать `http://localhost:3000`. Для YouTube можно указать ключ YouTube Data API v3; без него используется проверка страницы канала.

### 3. Запустите панель и бота

```bash
docker compose up -d --build admin
```

Направьте обратный прокси на адрес и порт панели, включите HTTPS и сохраните исходный заголовок `Host`. Откройте `PUBLIC_BASE_URL`, войдите через Discord и в разделе общих токенов сохраните токен бота и нужные API-ключи. Затем запустите бота:

```bash
docker compose up -d bot
docker compose logs -f admin bot
```

Добавьте бота на сервер, выберите сервер в панели, укажите канал и стримеров, затем сохраните настройки. Для остановки используйте `docker compose down`. Команда `docker compose down -v` также удалит сохранённые настройки, ключи и состояние доставки.

### Обновление

```bash
git pull
docker compose up -d --build
```

Оба контейнера используют volume `stream_notify_data`: в нём хранятся настройки серверов, секреты, состояние доставки и последняя сводка. Резервируйте volume в защищённом месте. Панель и бот должны работать с одним и тем же volume; запуск нескольких экземпляров бота с общей базой не предусмотрен. Перезапуск панели завершает активные сеансы входа.

## Настройка уведомлений

В настройках сервера выберите канал, формат сообщения и при необходимости роль. Для каждого стримера укажите имя и хотя бы один канал YouTube или логин Twitch. Участника Discord можно связать со стримером в форме добавления или редактирования.

В тексте доступны переменные:

| Переменная | Значение |
| --- | --- |
| `{name}` | Имя канала, полученное от платформы |
| `{streamer}` | Упоминание связанного участника Discord или имя канала |
| `{platform}` | Платформа трансляции |
| `{url}` | Ссылка на трансляцию |

Для простого сообщения ссылка добавляется автоматически, если её нет в шаблоне. При паузе стример остаётся в списке, а состояние трансляции продолжает обновляться. После возобновления уже идущий эфир может вызвать уведомление. Изменения списка стримеров сохраняются общей кнопкой настроек; переключение паузы сохранённого стримера применяется отдельно.

## Разработка

Нужен Python 3.12 или новее. Создайте окружение и установите зависимости:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Для локальной панели задайте `PUBLIC_BASE_URL=http://127.0.0.1:8765` и соответствующий Redirect URI в Discord. Запустите `python admin_web.py` и в другом терминале `python main.py`. Без `APP_DATA_DIR` настройки и секреты хранятся в каталоге проекта, а состояние — в `data/`.

```bash
python -B -m unittest discover
node --check static/admin.js
```

Основные компоненты: `admin_web.py` — веб-панель и OAuth, `main.py` и `monitor.py` — бот и мониторинг, `platforms/` — интеграции, `delivery_store.py` — состояние уведомлений, `static/` — интерфейс.
